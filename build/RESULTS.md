# 评测结果（阶段 1）

> 一套 20 题的评测集，两种检索方式，四组配置。所有数字都可以用
> `python step6_eval.py --file questions_hard.json ...` 复现。

## 测试条件

| 项 | 值 |
|---|---|
| 知识库 | 3 篇 Markdown，共 1746 字 |
| 切块 | 300 字/块，重叠 60 字 |
| 块数 | 9 |
| 评测集 | 20 题：16 道可答 + 4 道应拒答（同义改写版） |
| 生成模型 | deepseek-flash，`temperature=0.2` |
| Embedding | 阿里云百炼 `text-embedding-v3`，1024 维 |

## 结果

| # | 方案 | 阈值 | top-k | 总准确率 | 可答正确 | 拒答正确 |
|---|---|---|---|---|---|---|
| 1 | 关键词检索 | 0.3 | 3 | 35% | 3/16 | 4/4 |
| 2 | 关键词检索 | 0.1 | 3 | 70% | 10/16 | 4/4 |
| 3 | 关键词 + 查询改写 | 0.1 | 3 | 75% | 11/16 | 4/4 |
| 4 | 向量检索 | 0.45 | 3 | 80% | 12/16 | 4/4 |
| 5 | **向量检索** | **0.45** | **5** | **90%** | **14/16** | **4/4** |
| 6 | 向量检索 | 0.5 | 3 | 60% | 8/16 | 4/4 |

## 成本与延迟（单次问答，向量版）

| 指标 | 值 |
|---|---|
| 检索耗时 | ~1.5s（一次 embedding 请求） |
| 生成耗时 | ~0.8s |
| 总延迟 | ~2.3s |
| 输入 token | 约 730（5 块资料） |
| 输出 token | 约 20–40 |
| 单次成本 | 约 $0.00012（≈0.001 元） |
| 拒答成本 | $0（阈值拦截，不调模型） |

## 三个关键结论

1. **题目难度决定分数的意义。** 同一系统，照抄原文的题集 100%，同义改写后掉到 35%。评测集本身必须有难度，否则分数没有参考价值。

2. **改写的上限受限于打分函数。** 查询改写只提升 5 个百分点，因为字面匹配算不出语义相似；换成向量后，同一批题从 35% 升到 80%（同阈值下）。

3. **top-k 是性价比最高的一刀。** 3 → 5，准确率 +10 个点。答案块常常排在第 4、5 位，多给两块比调阈值更有效。

## 已知局限

- 知识库只有 9 块，数据量小，结论可能不随规模线性成立
- 向量阈值 0.45 是在本数据集上标定的，换文档要重新标定
- 没有 rerank：5 块直接塞给模型，模型自己挑
- 没有处理多轮对话：每次提问独立
- `vectors.json` 是本地文件，块数上千时需要向量库

## 复现命令

```powershell
# 关键词
python step6_eval.py --file questions_hard.json --min-score 0.1 --top-k 3

# 向量
python step6_eval.py --file questions_hard.json --mode vector --min-score 0.45 --top-k 5
```

# 附：FastAPI 文档知识库评测

## 知识库

FastAPI 官方文档（`docs/en/docs`）：158 篇，剔除变更日志/贡献指南等元信息后 138 个文件、1326 块，1024 维向量。

## 检索评测（20 题，`eval/questions_fastapi.json`）

每题标注应命中的源文件，统计 recall：

| 方案 | recall@1 | recall@5 | 检索耗时 |
|---|---|---|---|
| 向量检索 | 85% | 95% | 0.65s |
| 向量 + 中文问题翻译成英文 | 80% | **100%** | 2.2s |

结论：中文提问先翻译成英文再检索，recall@5 从 95% 提升到 100%；英文提问跳过翻译。

## 答案质量评测（20 题：15 可答 + 5 应拒答，`eval/questions_answer.json`）

生成温度固定 0，同一配置连跑两次结果一致：

| 指标 | 结果 |
|---|---|
| 总准确率 | **17/20 = 85%** |
| 可答正确 | 12/15 |
| 拒答正确 | 5/5 |
| 平均耗时 | 1.2s |
| 20 题总成本 | $0.0031 |

未通过的 3 题都依赖代码示例：

- 路径参数 `Path(gt=0)` 的写法
- 返回 404 时用 `HTTPException` 的写法
- OAuth2 + JWT 的完整登录流程

## 负向实验：保留代码块反而更差

把切块时丢弃的代码块保留（截断到 600 字符）后重新索引（1404 块），同一套题准确率从 **85% 降到 75%**。

原因：代码块挤占了 top-5 的位置，讲解文字被挤出上下文；模型看到的多是代码片段，反而给不出结论。

后续方向：把“讲解块”和“代码块”分开建索引，检索时各取一部分（双路召回）。
