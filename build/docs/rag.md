# RAG 检索增强生成速记

## 是什么
RAG 指检索增强生成：先从知识库里找出与问题相关的片段，再把这些片段作为上下文交给大模型，
让模型基于资料回答。它可以缓解模型不知道私有数据、以及容易编造的问题。

## 四个步骤
第一步是索引：把文档切分成小块，为每块计算向量或建立关键词索引。
第二步是检索：用户提问后，从索引里找出最相关的若干块。
第三步是增强：把检索到的块拼进提示词，要求模型只依据资料回答。
第四步是生成：模型输出答案，并标注引用了哪几块。

## 切块策略
块太长会超出上下文且噪声多，块太短会丢失语义。常见做法是按段落或标题切分，
每块控制在 200 到 500 字之间，相邻块之间保留一定重叠，避免答案被切断。

## 检索方式
关键词检索（如 BM25）依赖字面匹配，速度快，专有名词和代码标识符效果好。
向量检索依赖语义相似度，能处理同义表达，但需要嵌入模型。
实践中常用混合检索：两者各取一部分结果再重排。

## 评测
准备一批问题，为每个问题标注期望答案或关键词，然后批量提问并自动打分。
常用指标包括答对率、引用命中率、拒答准确率，以及单次回答的延迟与成本。
没有评测就无法判断改动是变好还是变坏。
