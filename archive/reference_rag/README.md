# 项目一：个人知识助手 v1

> 目标：把自己的文档变成一个"能回答、能给出处、答不上来说不知道"的助手。
> 主线项目，2–4 个半天。每天结束只记三行：能跑吗？答对几个？卡在哪？

## 为什么做这个

RAG（检索增强生成）= 检索 + 让模型基于资料回答。它是 AI 应用岗最核心的技能，
也把 `basics/` 里的所有概念串成一个真东西。

## 现在的结构

```
proj1_assistant/
├── llm.py      # 公共层：读配置、调模型、算成本（所有功能都用它）
├── rag.py      # 检索层：切块、打分、拼提示词
├── cli.py      # P1.0 命令行入口
├── app.py      # P1.1 HTTP 服务（/ask、/ask/stream、网页）
├── static/
│   └── index.html  # 网页前端
├── docs/       # 知识库（先放示例，再换成你自己的文档）
├── eval/       # P1.2 评测集
├── notes.md    # 每天三行
└── README.md
```

**分层的原因**：以后加接口、加网页、做评测，都复用 `llm.py` 和 `rag.py`，不重复写。

## 里程碑

| 阶段 | 做什么 | 验收 | 状态 |

## 验收永远这三样

1. **能跑**：命令敲下去有结果
2. **有数字**：答对几个、匹配度多少、花了多少 token
3. **能解释**：为什么选中这一块、为什么另一块没被选中
