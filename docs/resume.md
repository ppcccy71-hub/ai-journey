## 面试追问准备

**Q：为什么用 SQLite，不用 PostgreSQL？**
单实例部署，数据量在百万行以内，SQLite 单写多读够用且零运维；瓶颈在模型调用（秒级），存储是毫秒级，不是关键路径。要多实例部署时再换 PG，因为网络文件系统上的 SQLite 锁不可靠。

**Q：84% 是怎么测的？**
20 道题，15 道可答、5 道应拒答。可答题看答案是否包含关键标识（如 `Depends`、`TestClient`），拒答题看是否明确拒答；温度固定 0，连跑 5 次取均值，波动范围 80–90%。

**Q：为什么双路索引没提升？**
代码块能被检索到，但 top-5 位置固定，代码挤掉了讲解块，模型拿到的上下文反而更差。实测从 85% 降到 80%，所以回退。

**Q：怎么防止胡编？**
两层：检索最高分低于 0.45 直接拒答、不调模型；分数够但资料不含答案时，提示词要求模型回答“资料中没有相关信息”。5 道拒答题全部正确。

**Q：为什么中文问英文文档也能答？**
embedding 模型是多语言的，本身有一定跨语言能力；再加一步“翻译成英文再检索”作为双查询召回，recall@5 到 100%。

**Q：多知识库怎么做的？**
元数据进 SQLite，每个库一个向量文件；上传后后台线程切块、批量 embedding；默认检索全部库，选择器只用于缩小范围；Railway 挂卷后持久化。

**Q：成本怎么控制？**
单次约 $0.00015（生成部分），含翻译和 rerank 约 $0.0003–0.0005。拒答走阈值不调模型；统计页记录 token、成本和延迟。公开部署加了访问口令和 IP 限流，防止 key 被刷。
